# מדרום

מערכת קניון דיגיטלי מבוססת React, TypeScript, Cloudflare Pages Functions ו־D1.

## מצב נוכחי

המערכת כוללת קטלוג ציבורי, חנויות, מוצרים, סל, בקשות רכישה ללא חיוב, אזור סוחר, אזור מנהל ואזור לקוח. תשלומים אמיתיים עדיין חסומים במכוון עד לחיבור ספק סליקה Marketplace מאושר.

### חשבונות והרשאות

- כניסה אחידה למנהל, סוחר ולקוח.
- הרשמת לקוחות עם מייל וסיסמה.
- session cookie מאובטח.
- ניתוב אוטומטי לאזור המתאים לפי role.
- אזור לקוח עם עריכת שם וטלפון, היסטוריית בקשות רכישה והתראות פנימיות.
- תשתית DB מוכנה להרחבה ל־Google, קוד חד־פעמי במייל ו־SMS לאחר חיבור ספקים ו־Secrets.

### בקשות רכישה

הצעת המחיר מחושבת בשרת מתוך מחירי ומלאי המוצרים ב־D1. בקשה יכולה להתפצל למספר חנויות. משתמש מחובר נשמר כבעל הבקשה, והיסטוריית הבקשות מופיעה באזור האישי. אין חיוב ואין שמירת מלאי בשלב זה.

### התראות

נוצר מרכז התראות פנימי למשתמשים. לקוחות ובעלי חנויות מקבלים התראות במערכת על בקשות רכישה רלוונטיות, עם מונה לא־נקראו וסימון התראה בודדת או כולן כנקראו.

### מדיה

מוצר יכול להשתמש בקישור HTTPS או בהעלאת JPG/PNG/WebP ל־R2 כאשר binding בשם `MEDIA` מוגדר.

## פיתוח מקומי

```bash
npm ci
npm run dev
```

בדיקות לפני מיזוג:

```bash
npm run check
npm test
npm run build
```

GitHub Actions מריץ את שלוש הבדיקות אוטומטית בענפי `feature/**`, ב־Pull Requests וב־`main`.

## Cloudflare

יש להגדיר D1 binding בשם `DB` ולהריץ את כל קבצי `migrations/` לפי הסדר. עבור העלאת מדיה יש להגדיר R2 binding בשם `MEDIA`.

## אבטחה

- אין לשמור סודות בקוד או בגיט.
- כל פעולות הכתיבה ב־API בודקות same-origin.
- הרשאות מבודדות לפי role ו־store_id.
- אין לאפשר חיוב אמיתי לפני השלמת ספק סליקה, KYC, webhooks מאומתים, התאמות כספיות וחשבוניות.

למצב המפורט של כל תחום ראו `DELIVERY_STATUS.md` ו־`PAYMENT_INTEGRATION.md`.
